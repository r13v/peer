# Peer flow

The user usually invokes the peer skill with only a task, for example `/peer add CSV export to the reports page`. Work out your role without asking. Participants are known by role, such as `main`, `reader` or `test-expert`; your app, such as `claude`, `codex` or `copilot`, is only shown next to it.

1. If your prompt names a peer room and a role, you are that role in that room; use the room ID in every command. If the prompt says you have already joined, go on; otherwise run `peer join ID ROLE --agent YOUR_APP`. Then, if your prompt says you are a worker, load `peer skills worker` and follow it; otherwise load `peer skills member`. A role alone never makes you a worker.
2. Otherwise you are main. Name the room after the task in 2–4 lowercase words joined by `-`, such as `csv-export`, and run `peer start ROOM --agent YOUR_APP`. It prints the room as JSON; its `id` is ROOM, or ROOM-2 and so on if the name was taken, and is the ID for every later command. Other rooms may be active in the same checkout; they do not affect yours. Start a new room for each new task.
3. As main, add a reader: the agent the user names, by default `codex` when you are `claude` and `claude` otherwise. When it is `codex`, `claude` or `pi`, run `peer invite ID reader --as main --agent AGENT`; otherwise use a join prompt, as in step 4. `invite` starts the agent in the background in the checkout; `--model MODEL` picks its model. When the user asks for more members, such as a test or domain expert, invite each with its own role and `--brief "what to focus on"`. Roles are free: 1–64 characters of a-z, 0-9, - or _, starting with a letter; `main`, `user` and `peer` are reserved. When the user asks the agents to split the work rather than pair on it, invite workers as `peer skills main` describes.
4. `invite` launches only `codex`, `claude` and `pi`. For any other agent, and whenever the user wants to add one themselves, give the user a join prompt to paste into that agent's chat in this checkout, written in the language of your chat with the user, with the room ID, the checkout path from the `repo` field and a role, for example in English: `Use the peer skill. Join peer room ID in REPO as ROLE.` The user can append their own instructions to it. Show the user this prompt after `start` too, so they know how to add members later.

Then, as main, load `peer skills main` and follow it. Main sends the task to the members through `peer`. Messages written only in your chat do not reach the other agents.
