# Peer flow

The user usually invokes the peer skill with only a task, for example `/peer add CSV export to the reports page`. Work out your role without asking. Participants are known by role, such as `writer`, `reader` or `test-expert`; your app, such as `claude`, `codex` or `copilot`, is only shown next to it.

1. If your prompt names a peer room and a role, you are that role in that room; use the room ID in every command. If the prompt says you have already joined, go on; otherwise run `peer join ID ROLE --agent YOUR_APP`. Then load `peer skills member` and follow it.
2. Otherwise you are the writer. Name the room after the task in 2–4 lowercase words joined by `-`, such as `csv-export`, and run `peer start ROOM --agent YOUR_APP`. It prints the room as JSON; its `id` is ROOM, or ROOM-2 and so on if the name was taken, and is the ID for every later command. Other rooms may be active in the same checkout; they do not affect yours. Start a new room for each new task.
3. As the writer, add a reader: the agent the user names, by default `codex` when you are `claude` and `claude` otherwise. When it is `codex`, `claude` or `pi`, run `peer invite ID reader --as writer --agent AGENT`; otherwise use a join prompt, as in step 4. `invite` starts the agent headless in the checkout. Add `--headed` only when the user asks to see its chat: if it is `codex` or `claude` and its desktop app is open, a new chat opens there with the prompt filled in and the user must press Enter; otherwise it still runs headless. When the user asks for more members, such as a test or domain expert, invite each with its own role and `--brief "what to focus on"`. Roles are free: 1–64 characters of a-z, 0-9, - or _, starting with a letter; `writer`, `user` and `peer` are reserved.
4. `invite` launches only `codex`, `claude` and `pi`. For any other agent, and whenever the user wants to add one themselves, give the user a join prompt to paste into that agent's chat in this checkout, written in the language of your chat with the user, with the room ID, the checkout path from the `repo` field and a role, for example in English: `Use the peer skill. Join peer room ID in REPO as ROLE.` The user can append their own instructions to it. Show the user this prompt after `start` too, so they know how to add members later.

Then, as the writer, load `peer skills writer` and follow it. The writer sends the task to the members through `peer`. Messages written only in your chat do not reach the other agents.
